## 修掉容器凭证配置缺口（同日）

用户问"配应用凭证的流程是什么"，顺带核查发现 `docker-compose.yml` 的 `&backend_env` 有真实缺陷，已修：
1. **只透传了 TAOBAO_\*，抖店/拼多多凭证根本传不进容器** → 已补 `DOUYIN_APP_KEY/APP_SECRET/REDIRECT_URI`、`PDD_CLIENT_ID/CLIENT_SECRET/REDIRECT_URI`（三个平台 base url 在 config.py 已有默认值，无需透传）。
2. **`TOKEN_ENCRYPTION_KEYS` 硬编码了一个示例 Fernet key 作为默认值** → 缺失时会静默用示例密钥加密真实店铺 Token。已改为 `${TOKEN_ENCRYPTION_KEYS:?...}`，缺失则 compose 直接报错退出。
3. **回调地址不一致**：compose 里是 `localhost:8000`，`.env.example` 里是 `127.0.0.1:8000`（对平台回填是不同字符串）。已统一为 `127.0.0.1:8000`。

### 凭证配置路径约定（重要，后续直接引用）
- `Settings` 用 `env_file=".env"` 相对路径 → 加载哪个取决于**进程工作目录**。本地在 `backend/` 启动 → 读 `backend/.env`；容器/根 compose → 需 `--env-file .env` 显式注入 compose 变量。
- `.env` 与 `backend/.env` 都已在 .gitignore 中（安全）。
- 前置依赖：**先配 `TOKEN_ENCRYPTION_KEYS`（Fernet），否则即使有 App Key 也只会返回 409/credentials_required**。
- 回调端点是后端 JSON 接口（`GET /api/v1/integrations/{platform}/callback`），浏览器授权后会看到 JSON 而非跳转回前端——已知边界，前端需手动刷新状态。
