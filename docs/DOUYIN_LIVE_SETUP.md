# 抖店连接器：真实业务（live）接入手册

本手册说明抖店连接器真实读写链路的接入方式，以及**个人主体接入不可达时的验证基线**。

> 2026-10-12 依据抖音开放平台官方文档修订：早期版本中"控制台 → 常用工具 → 测试账号管理
> 免费领取测试店铺"的路径未经官方文档证实，且与现行文档不符，已移除。详见下方
> 「平台侧准入现实」一节。本文的平台侧规则来自官方文档（菜单名会随改版变动，以实际界面为准）；
> 代码侧行为以本仓库实现为准。

---

## 0. 平台侧准入现实（先读这一节）

抖店电商 API 与抖音生活服务 API 是两套体系，准入条件不同，不要混用：

| 体系 | 域名 | 个人主体 | 免费测试设施 |
|---|---|---|---|
| 抖店开放平台（电商：商品/订单/售后） | op.jinritemai.com | 不可达。需企业或个体工商户营业执照 + 对公验证，自研应用另需软件著作权等材料 | 未找到官方文档证实的免费测试店铺 |
| 抖音开放平台服务商平台（生活服务：团购券/核销/门店） | partner.open-douyin.com | 服务商入驻同样需主体资质 | 有「测试店铺管理」，位于解决方案接入详情页 → 验收准备下 |

生活服务「测试店铺管理」的完整前置链路（官方文档路径）：完成服务商入驻与解决方案能力权限开通 → 进入「代开发服务 → 第三方生活服务商家应用」选中应用 → 「解决方案」页点「接入解决方案」启动自助化接入 → 完成「基础配置 → 开发信息配置」→ 之后左侧导航才会出现「验收准备 → 测试店铺管理」。该设施验证的是生活服务 OpenAPI，**不能用于验证本项目的电商读写链路**。

抖店接口计费（2023 年 6 月起）：商家自研应用接口调用预充值制，敏感解密接口要求入云（云资源同样预充值）。

**结论**：个人无店铺主体当前无法完成抖店电商侧 live 联调。本项目的对应策略是契约测试兜底（`tests/test_douyin_live.py`，`httpx.MockTransport` 端到端覆盖 OAuth、同步与写接口），live 联调作为"待主体资质"状态记录，不用模拟结果冒充真实。

## 1. 平台侧准备（需要企业/个体户资质时）

1. 打开抖店开放平台 `op.jinritemai.com`，注册并完成企业认证（营业执照 + 法人信息，审核约 1 个工作日）。
2. 「控制台 → 应用 → 创建应用」，选择应用类型（自用型 / 工具型均可）。
3. 记录应用凭据：**Client Key → `DOUYIN_APP_KEY`**、**Client Secret → `DOUYIN_APP_SECRET`**。
4. 完成店铺授权：平台 OAuth 授权页同意后换取 token（现有页面上的「发起授权」按钮即此路径）。

---

## 2. 服务端配置

在 `.env`（本地开发在 `backend/.env`，容器部署用仓库根的 `.env`）填入：

```bash
DOUYIN_APP_KEY=<你的 Client Key>
DOUYIN_APP_SECRET=<你的 Client Secret>
DOUYIN_REDIRECT_URI=http://127.0.0.1:8000/api/v1/integrations/douyin/callback
TOKEN_ENCRYPTION_KEYS=<Fernet 主密钥>
```

`TOKEN_ENCRYPTION_KEYS` 是必需前置依赖（否则连接状态只会停在 `credentials_required`）：

```powershell
cd backend
uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

**回调地址必须与此处逐字符一致**，且要在开放平台应用的「回调地址」里登记同一个值
（`127.0.0.1` 与 `localhost` 在平台看来是两个不同地址）。

## 3. 授权 → 同步 → 读写

启动服务后访问前端 `/integrations`（侧栏「平台连接」）：

1. **发起授权**：抖店卡片点「发起授权」→ 新窗口打开平台 OAuth 页 → 同意后平台回调后端，
   完成换 Token、`shop.getShopInfo` 身份校验、Fernet 加密入库。
   > 回调是后端 JSON 接口，浏览器会显示一段 JSON 而非跳回页面——回到页面点「刷新」即可。
2. **同步真实商品**：状态变为「已连接」后点「**同步商品**」按钮，后端调用 `product.listV2` 拉取真实商品落库，并把该店铺的数据源切成 `live`。
   成功后卡片会显示：`共拉取 N 件｜新增 X / 更新 Y / 无变化 Z｜数据源 live`。
3. **真实写入**：在商品页对已同步到 `live` 店铺的商品执行改价/上下架，会真实调用
   `sku/editPrice`、`product/launchProduct`、`product/setOffline`，同时落审计日志并把
   任务的 `is_demo` 翻成 `false`。

### 工程语义（这些是刻意的设计，不是遗漏）

- **幂等**：批量任务靠 `idempotency_key` 去重；同步以平台商品 ID 做 upsert，重复同步不产生重复行。
- **真实 / 演示不混淆**：只有 `data_source=live` 且连接在 `ready` 状态才真实调用平台 API，
  否则只生成可审计的模拟任务，并如实标注 `is_demo=true`。**模拟结果绝不会被描述成真实授权数据**。
- **部分失败可重试**：逐商品产出结果行，失败项可单独重试（演示态下重试会恢复成功以演示链路）。
- **不编造平台没返回的字段**：商品列表接口不返回成本价、7 日销量与转化率，
  新建商品这些值为 0 并在同步结果的 `warnings` 里说明，成本价需在详情页自行维护。

## 4. 验收清单

| # | 检查项 | 期望 |
|---|---|---|
| 1 | `GET /api/v1/integrations/connectors` | douyin 的 `state=ready`、`missing_secrets=[]` |
| 2 | `POST /api/v1/integrations/douyin/sync` | 200，`is_live=true`，`created>0` |
| 3 | 同步后再同步一次 | `created=0`、`unchanged=N`（证明幂等） |
| 4 | 商品列表 | 出现来自抖店店铺的真实商品 |
| 5 | 对 live 商品改价 | 任务的 `is_demo=false`，审计 `is_demo=false` |
| 6 | 断开授权后再同步 | 409，明确提示「尚未完成授权」，不伪造数据 |

> 以上验收需要企业/个体户主体资质。个人主体请以 `tests/test_douyin_live.py` 的
> MockTransport 契约测试作为验证基线，它覆盖同一条代码路径，只是把网络层替换为模拟传输。
